# /changelog — 变更日志生成

根据 git 变更自动生成语义化 changelog 条目。

## 触发条件

- `/changelog`、`生成 changelog`、`更新 changelog`、`写 changelog`
- 或 commit 前自动触发

## 上游合并排除规则（硬规则）

以下内容**一律不得**新增或合并到 `changes/CHANGELOG.md`，也不得在 `changes/details/` 创建对应详情文件：

- `git fetch`、`pull`、`merge`、`rebase`、`cherry-pick` 等上游同步操作
- 合并提交、上游 commit 列表、合并统计、冲突文件、冲突解决策略和验证结果
- 直接来自 upstream 的功能、修复、依赖升级、文档调整或文件增删
- 仅为保持本地现有二开行为而做的冲突适配
- 文件名或标题类似 `upstream-merge`、`merge-upstream`、`sync-upstream` 的记录

禁止创建诸如“合并 upstream/main 的 N 个提交”一类条目。`changes/CHANGELOG.md` 只追踪本地相对上游新增或改变的二开行为。

如果上游合并期间额外实现了一个独立的本地功能或改变了本地业务行为，只记录该功能本身；说明中不得包含上游 commit、合并过程、冲突数量或同步背景。

## 工作流程

### 第 1 步：获取变更信息

```bash
# 查看暂存区变更（优先），若无暂存则查看工作区
git diff --cached --name-status 2>/dev/null || git diff --name-status

# 若上面为空，查看未跟踪文件 + 工作区变更
git status --porcelain
```

若变更仅涉及以下目录/文件，**无需生成 changelog**，直接告知用户跳过：

- `changes/`、`.cursor/`、`.agents/`、`.claude/`、`.codex/`、`.githooks/`、`.github/`
- `package-lock.json`、`bun.lockb`
- `AGENTS.md`、`CLAUDE.md`、`README.*.md`、`LICENSE`
- 纯格式化/注释变更

### 第 2 步：分析变更语义

读取每个变更文件的 diff 内容，理解改了什么、为什么改，用一句简洁中文概括。示例：

- "LDAP 登录时飞书同步改为同步调用，确保首次登录响应即包含头像"
- "移除 GitHub、Discord 等 OAuth 登录：删除后端提供商实现、前端界面及翻译"
- "侧边栏背景色改为透明（所有主题预设、明暗模式）"

### 第 3 步：检查是否需要合并

**在确定编号之前**，先读取 `changes/CHANGELOG.md` 的完整内容，判断本次变更是否与已有条目属于同一界面或同一功能。

判定标准（满足**任意一条**即视为同一功能）：

- 修改了已有条目详情列中的同名文件
- 修改了已有条目的详情文件中列出的文件
- 修改的文件路径与已有条目属于同一个 feature 目录（如 `src/features/auth/`、`src/features/home/`）
- 从 diff 内容判断是对同一功能的持续优化或补充

### 第 4 步：执行合并或新增

#### 合并（同一功能）

找到已有条目后，更新而非新增：

1. 更新已有条目的"说明"列，补充本次改动内容（用分号分隔或改写为更完整的描述）
2. 更新已有条目的"日期"为当前日期
3. 若已有条目是直接写文件路径（≤3 个），合并后总文件数仍 ≤3 则追加文件名；超过 3 则转为详情文件
4. 若已有条目有详情文件，在详情文件中追加本次涉及的文件说明

示例：已有条目 `010 | 2026-06-19 | Toast 关闭按钮位置由左上角改为右上角 | ...`，本次又修改了 toast 相关样式，则更新为：

```
| 010 | 2026-06-23 | Toast UI 优化：关闭按钮移至右上角、背景色微调 | ... |
```

#### 新增（不相关功能）

仅当本次变更与 CHANGELOG.md 中**所有已有条目均不相关**时，才新增编号。

### 第 5 步：确定编号（仅新增时）

```bash
# 读取当前最大编号
rg "^\\| (\\d+) " changes/CHANGELOG.md --no-line-number -r '$1' | sort -n | tail -1
```

新编号 = 最大编号 + 1，用 3 位零填充（如 `034`）。

### 第 6 步：按文件数量选择格式（仅新增时）

#### ≤3 个文件：直接在详情列写文件路径

在 `changes/CHANGELOG.md` 表末追加一行，详情列格式：

```
| 034 | YYYY-MM-DD | 一句话中文说明 | `path/to/file1.go`、`path/to/file2.tsx` |
```

#### >3 个文件：创建详情文件

创建 `changes/details/{编号}-{短标识}.md`，格式如下：

```markdown
# 一句话标题

**日期**: YYYY-MM-DD

## 涉及文件

- `path/to/file1` — 具体改动说明
- `path/to/file2` — 具体改动说明
```

短标识用英文 kebab-case，提取自说明中的核心关键词，如 `ldap-sync-fix`、`remove-oauth`。

然后在 CHANGELOG.md 详情列写：

```
| 034 | YYYY-MM-DD | 一句话中文说明 | [详情](details/034-ldap-sync-fix.md) |
```

### 第 7 步：写入 CHANGELOG.md

用 Edit 工具修改 `changes/CHANGELOG.md`（合并场景修改已有行，新增场景在末尾追加）。确保：

- 表格列对齐
- 编号 3 位零填充
- 日期格式 `YYYY-MM-DD`

### 第 8 步：添加变更到 git 暂存区

```bash
git add changes/CHANGELOG.md
# 若有详情文件
git add changes/details/{编号}-{短标识}.md
```

### 第 9 步：输出确认

向用户展示操作结果：

```
✅ changelog 已更新：

  操作: 合并到 #010（Toast UI 优化）
  说明: Toast 关闭按钮移至右上角、背景色微调

或

✅ changelog 已生成：

  编号: 034
  说明: LDAP 登录时飞书同步改为同步调用
  详情: `controller/ldap.go`、`service/feishu_sync.go`
```

## 关键规则

1. **所有说明文字必须是中文**
2. **编号必须 3 位零填充**（`001`、`012`、`134`）
3. **详情列 ≤3 个文件时直接写文件名，用顿号分隔不用逗号**
4. **详情列 >3 个文件时用 `[详情](details/xxx.md)` 链接**
5. **纯格式化/注释等无需记录的变更直接告知用户跳过**
6. **同一界面/功能的连续修改必须合并到已有条目，不要新增编号**
7. **仅在变更与所有已有条目均不相关时，才新增编号并在末尾追加**
8. **上游同步、合并过程和纯上游改动永不记录；不得创建 upstream-merge 详情文件**

## 合并与新增规则（详细）

| 场景 | 操作 |
|------|------|
| 改的是已有条目中的同名文件 | **合并**：更新说明、日期、文件列表 |
| 改的是已有条目详情文件中列出的文件 | **合并**：更新说明、日期、详情文件 |
| 改的文件与已有条目同属一个 feature 目录 | **合并**：更新说明、日期 |
| 从 diff 判断是对同一功能的持续优化 | **合并**：更新说明、日期 |
| 变更与所有已有条目均无关联 | **新增**：确定编号、追加行 |

**合并时不需要递增编号，原编号不变。**

## 编号格式

CHANGELOG.md 中编号列统一 3 位零填充：`| 001 |`、`| 012 |`、`| 134 |`。

读取最大编号时排除可能的重复（如同一编号出现多次），取最新一行的编号。

## 短标识命名

详情文件的短标识从说明中提取核心关键词，用英文 kebab-case：

- "LDAP 登录时飞书同步改为同步调用" → `ldap-sync`
- "修复侧边栏选中项悬停时文字颜色被覆盖" → `sidebar-hover-color`
- "移除邀请人/邀请码功能" → `remove-invitation`

控制在 3-5 个单词，不要过长。
