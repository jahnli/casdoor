# 单 LDAP 组织同步清理缺失人员

**日期**：2026-11-17

组织只配置一个 LDAP 时，同步流程新增缺失人员清理。复用用户已有的 `ldap` 标识，不增加数据库字段，保留现有逐用户新增、更新及定时调度机制。

## 执行顺序

- 定时同步：成功获取完整 LDAP 用户名单，清理缺失人员，再同步组和用户；清理报错时停止本轮，后续同步失败不会回滚已经完成的删除。
- 手动同步：先同步用户勾选的人员，仅在没有同步错误或失败人员时，重新连接 LDAP 获取完整名单并清理；不以勾选名单判断删除，响应增加删除数量。

## 删除范围与限制

- 只检查当前组织内 `ldap` 非空且尚未软删除的用户，按现有 UUID、用户名或名称回退规则与完整名单比较；本地未关联 LDAP 的账号和其他组织账号不参与清理。
- 对缺失候选人员，在当前基础 DN 范围内再次按 LDAP 标识查询，检查不附加名单过滤器，避免仅因过滤条件收窄而删除仍可查到的账号；查到任何匹配项即保留。
- 完整名单为空时跳过清理；标识缺失、组织配置多个 LDAP、读取名单后相关连接或搜索范围配置发生变化时拒绝清理。候选人员复查报错、返回转介或无有效查询结果时停止后续清理，不回滚此前已完成的删除。
- 删除前重新读取用户，跳过已经软删除或 LDAP 标识已变化的账号，调用现有用户删除方法清理访问会话、使令牌过期，并清理组授权关系、独立第三方绑定记录和密码历史；遵循组织软删除设置，后续清理不会主动将软删除账号永久删除。
- 软删除继续保留用户记录及原用户名、手机号，不释放这些值供管理界面重复创建，也不增加 LDAP 用户重新出现时的自动恢复逻辑。
- 本次未增加批量更新优化或共用执行锁；手动与定时同步，以及多实例长时间同步的并发边界沿用现有机制。

## 涉及文件

- `object/ldap_cleanup.go` — 实现完整名单获取、单 LDAP 配置校验、删除范围筛选、候选人员复查及现有删除流程调用，记录清理结果。
- `object/ldap_autosync.go` — 将完整名单获取及缺失人员清理放在组和用户同步之前，清理失败停止本轮，成功日志附带删除数量。
- `controllers/ldap.go` — 手动同步成功后单独获取完整名单进行清理，接口响应增加删除数量，清理失败返回已删除数量和错误信息。
- `object/ldap_cleanup_test.go` — 覆盖普通删除与软删除、重复清理、本地和跨组织账号保留、标识回退、过滤后仍存在的账号保留、关联数据清理、异常名单与复查失败及过滤值转义。
